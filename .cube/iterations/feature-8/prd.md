# 迭代 8 PRD：模板、角色与模型策略

## 1. 功能概述

本次迭代聚焦把“模板”从静态展示升级为可驱动新会话创建的真实配置源，并让首页、模板页、会话恢复链路与模型策略能力形成闭环。

本次迭代包含以下功能点：

1. 模板中心展示真实模板数据，覆盖概览、角色、事件、节奏四类信息。
2. 首页支持选择模板与模型策略，并将选择结果带入新会话创建。
3. 模板页支持查看角色详情与调整角色轻量配置。
4. 新会话创建后进入对应讨论详情页，历史会话恢复时保持创建当时的模板与策略一致性。
5. 模型策略不只是展示项，必须真实影响后续多角色讨论的模型选择与生成表现。

## 2. Functional Requirements

### 功能点 A：模板中心与模板详情

**FR-001（P0）** 模板中心必须展示真实模板列表，而不是组件内硬编码内容。  
- 输入：用户进入模板页。  
- 输出：用户看到模板名称、简介、标签、角色数量、事件数量、使用数据等摘要信息。  
- 异常处理：当模板数据为空时，页面显示“暂无模板”状态；当加载失败时，页面显示明确的失败提示与重试入口。

**FR-002（P0）** 用户进入模板详情后，必须能查看模板的基础信息与价值说明。  
- 输入：用户点击某个模板。  
- 输出：页面展示模板名称、描述、分类、标签、使用数据，以及该模板适用场景与用户身份说明。  
- 异常处理：当模板不存在或已不可用时，页面提示模板不可访问，并提供返回模板列表的入口。

**FR-003（P0）** 模板详情必须支持“概览 / 角色 / 事件 / 节奏”四个 Tab 的切换。  
- 输入：用户切换模板详情 Tab。  
- 输出：页面展示与当前 Tab 对应的真实数据内容。  
- 异常处理：当某一类数据为空时，显示该类内容为空的说明，不影响其他 Tab 使用。

**FR-004（P1）** 模板页中的“使用模板”操作必须服务于新会话创建，而不能绕过会话创建链路直接进入讨论页面。  
- 输入：用户在模板详情页点击“使用模板”。  
- 输出：系统将所选模板带入新会话创建流程，最终由创建成功的新会话进入讨论详情页。  
- 异常处理：当模板当前不可用于创建会话时，页面提示原因，并保留用户返回或重新选择模板的能力。

### 功能点 B：角色查看与角色轻量配置

**FR-005（P0）** 模板详情的角色 Tab 必须展示完整角色列表。  
- 输入：用户进入角色 Tab。  
- 输出：页面展示角色名称、人设描述、当前模型、配置状态等信息。  
- 异常处理：当角色列表为空时，页面提示该模板暂无角色配置，且不出现误导性的可操作入口。

**FR-006（P1）** 用户必须能查看单个角色的详情信息。  
- 输入：用户点击角色详情入口。  
- 输出：系统展示该角色的定位说明、角色提示词摘要、默认模型和相关配置说明。  
- 异常处理：当角色详情加载失败时，系统提示无法获取角色详情，并允许用户关闭弹层或重试。

**FR-007（P1）** 用户必须能调整模板角色的轻量配置，至少包括默认模型与发言长度。  
- 输入：用户在角色配置面板中调整配置并保存。  
- 输出：系统保存角色配置，并在模板视角中反映新的默认配置状态。  
- 异常处理：当提交内容无效、保存失败或模板不可编辑时，系统显示清晰错误提示，且不应造成页面展示与实际保存结果不一致。

**FR-008（P0）** 角色配置变更只影响后续新会话或模板未来使用，不影响已创建历史会话。  
- 输入：用户修改模板角色配置后，再查看历史会话。  
- 输出：历史会话仍展示并使用创建当时的角色配置；新会话使用最新模板配置。  
- 异常处理：当系统无法判断历史会话配置来源时，应优先保证历史会话内容稳定可恢复，而不是强行套用新模板配置。

### 功能点 C：首页模板与模型策略选择

**FR-009（P0）** 首页必须支持从真实模板数据中选择讨论模板。  
- 输入：用户在首页打开模板选择面板并选择模板。  
- 输出：首页展示当前选中的模板摘要信息，供用户发起新讨论使用。  
- 异常处理：当模板列表加载失败时，页面提示加载失败；当用户未完成选择时，系统保留默认模板或阻止进入不完整的创建流程。

**FR-010（P0）** 首页必须支持选择模型策略，并清晰说明策略差异。  
- 输入：用户在首页打开模型策略面板并选择策略。  
- 输出：页面展示当前选中的策略名称与定位，如质量优先、成本优先、智能平衡等。  
- 异常处理：当策略列表加载失败或策略暂不可用时，系统提示失败原因，并保留默认策略或阻止提交无效策略。

**FR-011（P0）** 用户在首页发起新讨论时，系统必须使用用户当前选择的模板与模型策略创建会话。  
- 输入：用户输入议题，并携带已选择的模板与模型策略发起讨论。  
- 输出：系统创建新会话，并将模板选择与模型策略选择绑定到该会话。  
- 异常处理：当议题为空、模板无效、策略无效或会话创建失败时，系统应阻止进入讨论详情页，并给出明确反馈。

**FR-012（P0）** 新会话创建成功后，系统必须进入对应的讨论详情页。  
- 输入：会话创建成功。  
- 输出：用户进入与该会话绑定的讨论详情页，看到与所选模板一致的讨论上下文。  
- 异常处理：当跳转失败或会话详情无法加载时，系统提示进入失败，并提供返回首页或重试加载的入口。

### 功能点 D：模型策略的真实消费与会话一致性

**FR-013（P0）** 模型策略必须真实影响后续多角色讨论的生成表现，而不是仅停留在界面展示。  
- 输入：用户为新会话选择某个模型策略。  
- 输出：该会话中的角色讨论表现应与策略目标一致，例如更偏质量、更偏成本或更偏速度。  
- 异常处理：当所选策略当前无法完整生效时，系统应使用可接受的兜底策略继续讨论，并避免让用户误以为策略已完全生效。

**FR-014（P0）** 历史会话恢复时，必须优先保持创建当时所使用的模板与模型策略一致性。  
- 输入：用户从会话列表恢复历史会话。  
- 输出：系统按该会话创建时的模板与模型策略恢复讨论上下文，而不是应用模板中心的最新内容。  
- 异常处理：当历史会话部分配置缺失时，系统应优先恢复可用的历史上下文，并清晰提示哪些信息使用了兜底值。

**FR-015（P1）** 会话列表与恢复入口应能体现该会话与模板的关联，帮助用户快速识别上下文。  
- 输入：用户查看会话列表。  
- 输出：列表展示模板名称、角色数量、事件/消息数量、时间等摘要信息。  
- 异常处理：当摘要信息不完整时，系统至少保证会话可识别与可恢复，不因部分统计缺失阻断使用。

## 3. Non-Functional Requirements

**NFR-001** 一致性要求：模板页、首页模板选择面板、历史会话恢复所使用的模板信息必须来源一致，避免同一模板在不同入口展示不一致。  

**NFR-002** 可理解性要求：模型策略必须对用户呈现清晰可理解的差异说明，避免用户无法判断“质量优先 / 成本优先 / 智能平衡”等策略的实际含义。  

**NFR-003** 稳定性要求：历史会话恢复必须优先保证上下文稳定，不因模板后续修改、角色配置更新或策略调整导致历史会话内容漂移。  

**NFR-004** 交互性能要求：模板中心、模板详情、首页模板/策略选择等高频页面应在正常网络与本地数据环境下保持流畅切换，不出现明显阻塞用户操作的等待体验。  

**NFR-005** 兼容性要求：本迭代涉及的首页、模板页、会话页核心交互需与当前移动端原型结构保持一致，避免一级导航与讨论详情页关系被破坏。  

## 4. 验收标准

1. 用户进入模板中心后，可以看到真实模板列表，而不是固定写死的展示数据。  
2. 用户进入模板详情后，可以在概览、角色、事件、节奏四个 Tab 之间切换并看到对应内容。  
3. 角色 Tab 中能看到角色名称、人设、模型和配置状态。  
4. 用户可以打开角色详情查看角色说明与默认配置。  
5. 用户可以修改角色默认模型与发言长度，并获得明确保存结果反馈。  
6. 修改角色配置后，新会话可使用新配置，已创建历史会话仍保持原配置。  
7. 首页可以选择模板，并看到当前所选模板摘要。  
8. 首页可以选择模型策略，并看到当前所选策略说明。  
9. 用户输入议题后创建新会话，系统会使用当前所选模板与模型策略。  
10. 新会话创建成功后，用户进入对应的讨论详情页，而不是停留在首页或进入无会话上下文的讨论页面。  
11. 用户从会话列表恢复历史会话时，看到的模板与策略效果与该会话创建时保持一致。  
12. 模型策略的选择能真实影响后续讨论表现，而不是仅改变首页显示文案。  
13. 当模板、角色、策略或会话数据加载失败时，页面能给出明确错误提示，并保留重试、返回或继续使用默认值的合理路径。  

## 5. Out of Scope

1. 服务端模板动态下发、CDN 分发与模板远程同步。  
2. 复杂模板编辑器、可视化模板搭建能力。  
3. 社区模板市场、模板分享与模板运营体系。  
4. Provider 配置、API Key 管理和全局模型设置能力。  
5. 在模板页直接触发真实讨论事件或绕过会话创建链路进入讨论。  
6. 对历史会话进行回写式模板升级或策略升级。  

## 6. 依赖说明

1. 依赖现有会话创建链路支持“议题 + 模板 + 模型策略”的会话发起方式。  
2. 依赖模板数据、角色数据、模型策略数据能够作为统一来源被首页、模板页、会话恢复链路共同消费。  
3. 依赖讨论详情页继续承接新会话创建成功后的跳转与历史会话恢复入口。
